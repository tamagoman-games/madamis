# マーダーミステリー ― オンライン版（深夜0時の館 / 消えた魔女の遺産）

部屋コードで友達と遊べる、ブラウザ用マーダーミステリー（マダミス）です。スマホ縦画面向け。GMなしで、システムが自動進行します。
Node.js 18以上が必要です。ゲームサーバーの実行時依存はゼロで、`npm install` はテストツールの依存関係を準備します。

## シナリオ

| シナリオ | 人数 | 内容 |
|---|---|---|
| 深夜0時の館 | 3〜5人 | 本格ミステリー（既存）。5人未満なら余った役はNPC |
| 消えた魔女の遺産 | **4〜5人（4人推奨）** | ファンタジー・ミステリー。**4人なら4人版、5人なら5人版**が自動で選ばれる |

ロビーで**ホストだけ**がシナリオを選べます（全員の画面に同期）。開始後は変更できません。

### 消えた魔女の遺産
人里離れた魔術師の館「月影の館」。魔女リゼットの死後、公開直前の「魔女の遺産」が、吹雪の夜に封印庫から消えた。外へ出た足跡はない。犯人はこの中にいる。

- **4人版**: エルヴィン（弟子）／マルグリット（家政婦）／ジークハルト（公証人）／ノエル（薬師）。犯人は**ジークハルト**
- **5人版**: 上の4人に**カミラ（魔術師ギルドの検査官）**が加わる。追加の秘密・人間関係・証拠があり、犯人は**カミラ**に変わる
- 犯人以外の全員も、事件とは別の「やましい秘密」を持っていて、全員が怪しく見える。証拠を整理すれば論理的に犯人を特定できる
- 犯人特定に必要な事実は、すべて「公開証拠」か「2人以上が持つ情報」で裏付けてある（密談しなくても推理できる。密談するとより早く確実になる）。`npm test` が自動検証します
- 目標は人によって違う：犯人を当てる（探偵役）／秘密を守る／遺産の一部を手に入れる／犯人は逃げ切る。結果発表で達成度を判定し、個人エンディングを表示します

進行：オープニング → キャラクター確認 → 第一調査 → 第一議論 → 第二調査 → 第二議論 → 最終議論 → 投票 → 結果発表 → 真相 → 個人エンディング

## 密談（2人だけの専用チャット）

1. 議論のフェーズ中に「密談する」を押し、相手を選んで申請
2. 相手に「○○から密談の申請が届いています」と表示 → **許可 / 拒否**
3. 許可されると、双方に「密談：○○」画面が開く（相手の名前・チャット・入力・送信・密談終了）
4. 全体チャットとは完全に分離

**セキュリティ**: 密談の状態・メッセージはサーバー（`secret.js`）だけが持ち、**参加者2人の接続にだけ**送信します。第三者のブラウザには、メッセージも申請の存在も一切送られません（画面上で隠しているのではなく、そもそも届きません）。`npm test` が、第三者が受信した全データに密談の内容が含まれないことを検証します。

ルール（`secret.js` の `RULES` で調整）：人数は2人／同時に参加できるのは1人1組／議論フェーズ中のみ／回数は無制限（環境変数 `SECRET_MAX_PER_PLAYER` で1人あたりの回数を制限できる構造）。申請は60秒で時間切れ。議論が終わると、進行中の密談は自動で終了します。

## 技術構成

| 役割 | 採用 | 理由 |
|---|---|---|
| サーバー | Node.js 標準の `http` | 無料枠のホスティングにそのまま載る |
| リアルタイム配信 | **SSE (Server-Sent Events)** | WebSocketより単純で、スマホの回線切替後も自動再接続される |
| 操作 | `fetch` の POST | 1操作=1リクエスト。認証トークン付き |
| フロント | 素のHTML/CSS/JS（ビルド不要） | サーバーが配信。別ドメインにも置ける |
| ゲーム状態 | サーバーのメモリ | 部屋・役・秘密・証拠・密談・投票・タイマーはすべてサーバーが保持 |

## 秘密情報のセキュリティ

- 全員分の秘密は **サーバー（`scenario.js` / `scenario-witch.js`）にだけ** あり、HTML/JSには入っていません。サーバーは画面ファイル4つ（`index.html` `style.css` `app.js` `config.js`）しか配信しません。
- クライアントへは `viewFor()`（`game.js`）が作った「**その人が見てよい分だけ**」を送ります。他人の投票は結果発表まで届かず、犯人の正体も結果発表まで届きません。

## ローカルで起動

GitHubへはこのフォルダの**中身をリポジトリのルートとして**保存できます。

```bash
npm install
npm start
# → http://localhost:3000
```

同じWi-Fiのスマホで試すときは `http://<PCのIPアドレス>:3000` を開きます。1台のPCで複数人を試すときは、シークレットウィンドウや別ブラウザで開いてください。

テスト：

```bash
npm test                                   # 4人/5人/密談/公平性を含む通信テスト
npx playwright install chromium
npm run test:ui                            # スマホ幅のブラウザUIテスト
```

## オンラインに公開する（無料）

### A. Render.com（いちばん簡単）
1. このフォルダの中身をGitHubリポジトリのルートにアップロード
2. Render で **New + → Blueprint**（または Web Service）→ リポジトリを選ぶ。`render.yaml` が自動で読まれます
3. 発行された `https://xxxx.onrender.com` を友達に送る → 完成

無料プランは、しばらく誰も使わないとスリープし、次のアクセスで10〜30秒ほどかかります。遊ぶ直前に一度開いておくと安心です。サーバーを再起動すると進行中の部屋は消えます（メモリ保持のため）。

### ReplitなどNode.js対応サービス

Node.jsの実行環境で `npm install` を行い、起動コマンドを `npm start` に設定します。待ち受けポートは環境変数 `PORT` に従います。GitHub PagesだけではNode.jsサーバーやSSEを動かせないため、このゲームは動作しません。

### B. Docker が使えるサービス（Fly.io / Railway / Koyeb / Cloud Run など）
`Dockerfile` を使います。ポートは環境変数 `PORT` に自動で従います。

### C. クライアントだけ別ドメイン（Cloudflare Pages など）に置く場合
1. 画面ファイル4つを静的ホスティングに配置し、`config.js` の `API_BASE` にサーバーのURLを入れる
2. サーバー側で環境変数 `CORS_ORIGIN` に、クライアントのURLを設定

> 注意: サーバーは **1台だけ** で動かしてください。部屋の状態はメモリにあるため、複数台に分けると別々の部屋になります。

## 環境変数（すべて任意。変数名のみを記した`.env.example`参照）

| 名前 | 既定値 | 説明 |
|---|---|---|
| `PORT` | 3000 | 待ち受けポート |
| `HOST` | 0.0.0.0 | 待ち受けアドレス |
| `CORS_ORIGIN` | なし | クライアントを別ドメインに置くときだけ設定 |
| `MAX_ROOMS` | 500 | 同時に存在できる部屋数の上限 |
| `ROOM_TTL_MIN` | 180 | 誰も接続していない部屋を消すまでの分数 |
| `LOBBY_GRACE_SEC` | 60 | ロビーで接続が切れた人を除外するまでの秒数 |
| `MIN_PHASE_SEC` | 10 | 制限時間設定の下限（秒）。テスト用 |
| `SECRET_MAX_PER_PLAYER` | 無制限 | 密談を1人あたり何回まで始められるか |

## 遊び方の流れ

ロビー → （ホストがシナリオ選択）→ 開始 → 各フェーズ。各フェーズは制限時間（ロビーで変更可）が過ぎるか、全員が「次へ進む」を押すと進みます。残り時間はサーバー基準で全員同じです。

- **再接続**: ページ更新・通信断・ブラウザ復帰のあと、自動で同じ部屋・同じ状況に戻ります（密談の履歴も、参加していた本人にだけ戻ります）。
- **途中退出**: 「○○が退出しました」と表示され、そのキャラはNPCになり、進行は止まりません。密談中なら相手に通知されて密談は終了します。退出した人の「公開してよい情報」は自動で公開され、推理が止まりません。ホストが抜けたら次の人がホストになります。
- **人数が変わっても**: ゲーム開始時に人数に合う版が確定し、以降は変わりません。
