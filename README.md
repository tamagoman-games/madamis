# 深夜0時の館 ― オンライン・マーダーミステリー

部屋コードで友達と遊べる、ブラウザ用マーダーミステリー（マダミス）です。スマホ縦画面向け。GMなしで、システムが自動進行します。
**依存パッケージはゼロ**（Node.js 18以上だけで動きます。`npm install` 不要）。

## 技術構成と選んだ理由

| 役割 | 採用 | 理由 |
|---|---|---|
| サーバー | Node.js 標準の `http` | 無料枠のホスティング（Render / Fly.io / Railway / Koyeb など）にそのまま載る |
| リアルタイム配信（サーバー→全員） | **SSE (Server-Sent Events)** | WebSocketより通信が単純で、スマホの回線切替後も自動再接続される。プロキシ・無料枠との相性が良い |
| 操作（全員→サーバー） | `fetch` の POST | 1操作=1リクエスト。認証トークン付き |
| フロント | 素のHTML/CSS/JS（ビルド不要） | 画面ファイルをサーバーが配信。別ドメインにも置ける |
| ゲーム状態 | サーバーのメモリ | 部屋・役・秘密・証拠・投票・タイマーはすべてサーバーが保持 |

Socket.IO / Firebase / Supabase / Cloudflare も検討しましたが、「1つのURLを無料で公開して、友達と遊べる」ことを最優先し、
外部サービスのアカウントが不要な構成にしました。

## 秘密情報のセキュリティ

- 全員分の秘密は **サーバー（`scenario.js`）にだけ** あり、HTML/JSには入っていません。
- クライアントへは `viewFor()`（`game.js`）が作った「**その人が見てよい分だけ**」を送ります。
  - 自分のキャラの秘密・目的・知っている情報だけが届く（しかも、公開される段階になるまで届かない）
  - 他人の投票は結果発表まで届かない。犯人の正体も結果発表まで届かない
- `npm test` が「他人の秘密が1バイトも届いていない」ことを自動検証します。

## ローカルで起動

```bash
node server.js
# → http://localhost:3000
```

同じWi-Fiのスマホで試すときは `http://<PCのIPアドレス>:3000` を開きます。
1台のPCで複数人を試すときは、シークレットウィンドウや別ブラウザで開いてください（同じブラウザだと同じ参加者になります）。

テスト:

```bash
npm test                                   # サーバー＋5人分のクライアントで全フェーズを通す
NODE_PATH=$(npm root -g) npm run test:ui   # スマホ幅のブラウザで実際にボタンを押して通す（要 playwright）
```

## オンラインに公開する（無料）

### A. Render.com（いちばん簡単）
1. このフォルダをGitHubにアップロード
2. Render で **New + → Blueprint**（または Web Service）→ リポジトリを選ぶ。`render.yaml` が自動で読まれます
3. 発行された `https://xxxx.onrender.com` を友達に送る → 完成

無料プランは、しばらく誰も使わないとスリープし、次のアクセスで10〜30秒ほどかかります。遊ぶ直前に一度開いておくと安心です。
サーバーを再起動すると進行中の部屋は消えます（メモリ保持のため）。

### B. Docker が使えるサービス（Fly.io / Railway / Koyeb / Cloud Run など）
`Dockerfile` を使います。ポートは環境変数 `PORT` に自動で従います。

```bash
fly launch   # Fly.io の例
```

### C. クライアントだけ別ドメイン（Cloudflare Pages など）に置く場合
1. `index.html` `style.css` `app.js` `config.js` を静的ホスティングに配置し、`config.js` の `API_BASE` にサーバーのURLを入れる
2. サーバー側で環境変数 `CORS_ORIGIN` に、クライアントのURL（例 `https://xxx.pages.dev`）を設定

> 注意: 無料枠でも **サーバーを1台だけ** で動かしてください。部屋の状態はメモリにあるため、複数台に分けると別々の部屋になります。

## 環境変数

`.env.example` を参照（すべて任意）。

| 名前 | 既定値 | 説明 |
|---|---|---|
| `PORT` | 3000 | 待ち受けポート（ホスティングが自動設定することが多い） |
| `HOST` | 0.0.0.0 | 待ち受けアドレス |
| `CORS_ORIGIN` | なし | クライアントを別ドメインに置くときだけ設定 |
| `MAX_ROOMS` | 500 | 同時に存在できる部屋数の上限 |
| `ROOM_TTL_MIN` | 180 | 誰も接続していない部屋を消すまでの分数 |
| `LOBBY_GRACE_SEC` | 60 | ロビーで接続が切れた人を除外するまでの秒数 |
| `MIN_PHASE_SEC` | 10 | 制限時間設定の下限（秒）。テスト用 |

## ファイル構成（フォルダなし・すべて同じ階層）

```
server.js       HTTP・SSE・API・静的配信
game.js         部屋/フェーズ/タイマー/投票/結果/プレイヤー別ビュー
scenario.js     シナリオ「深夜0時の館」（秘密・証拠・真相・エンディング）
index.html / style.css / app.js / config.js   画面（クライアント）
test-smoke.js   通信テスト（5人・秘密漏洩チェック）
test-ui.js      ブラウザUIテスト（Playwright）
package.json / Dockerfile / render.yaml / .env.example / README.md
```
サーバーは `index.html` `style.css` `app.js` `config.js` の4つだけを配信します（`game.js` などのソースは外から取得できません）。

## 遊び方の流れ

ロビー → キャラクター決定 → オープニング → 個人情報確認 → 情報公開（場所を調べる・証拠を公開）→ 議論 → 追加情報 → 最終議論 → 投票 → 結果発表 → エンディング。
各フェーズは制限時間（ロビーで変更可）が過ぎるか、全員が「次へ進む」を押すと進みます。残り時間はサーバー基準で全員同じです。

- **再接続**: ページ更新・通信断・ブラウザ復帰のあと、自動で同じ部屋・同じ状況に戻ります（端末に保存したトークンで本人確認）。
- **途中退出**: 「○○が退出しました」と表示され、ゲーム中ならそのキャラはNPCになり、進行は止まりません。ホストが抜けた場合は自動で次の人がホストに。
- **人数**: 3〜5人。5人未満なら余った役はNPCになります（NPCの公開できる情報は、情報公開フェーズで自動的に公開されます）。犯人役は必ず人間に割り当てられます。
